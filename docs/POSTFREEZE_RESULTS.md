# Post-freeze challenge and SR01 recovery extension: results summary

The records named below are part of the separate evidence object (see
`docs/FULL_EVIDENCE.md`); the gate commands need that evidence attached.

The unchanged fourteen-relation catalog was evaluated after its source identity was frozen. Four separately implemented behaviors exercise a key-omitting positive cache, a latched rejection, basename-based artifact resolution and fallback to a previously accepted native artifact. These are new triggers within known contract families, selected by designers familiar with the catalog. Eighty-four predefined separation traces distinguish their concrete actions from selected original operators. Each full pass then evaluates 18 hosts, three carriers, CLEAN and all four behaviors under all fourteen relations, for 3,780 cases. A separately executed MR01-only pass contains 270 cases. The complete catalog exposes 162 of 216 seeded host/carrier/behavior instances in each pass; the MR01-only baseline exposes none. The 54 N02 instances remain unexposed because the frozen catalog does not request a valid extraction after a typed-negative response. All 756 clean cases satisfy the full catalog in each pass. Two complete passes agree on all 41,580 non-timing field comparisons; the standalone MR01 rerun agrees on 2,970 fields.

The full passes take 102.485 and 111.566 wall seconds; the separate MR01 passes take 4.746 and 4.546 seconds. Each full pass records 5,940 compiler driver invocation attempts, compared with 270 in each MR01 pass. These four-worker local measurements include record retention and are recorded in counterbalanced order on a shared host. The additional adapter wrapper has 145 nonblank lines; the six challenge producer files contain 700 lines in total under a rule that includes comments and docstrings. These counts do not estimate human integration effort.

The missed N02 transition motivated a separate adaptive recovery obligation, SR01. Its premise requires a target contract that permits immediate reuse of the same decoder after rejection and excludes lockout. Source validity is independently observed; a tested correct-key extraction, a typed wrong-key rejection, retained endpoint byte identities and the subsequent correct-key result establish the sequence. Across two passes of 270 cases, each pass has 54 satisfied clean cases, 54 inconsistent reusable N02 cases and 162 inadmissible boundary cases. The boundaries separately permit lockout, fail to establish a typed rejection because N01 accepts the wrong key, and replace the original artifact with a separately compiled second-payload artifact before recovery. The 3,240 non-timing comparisons across passes contain no differences. SR01 is an adaptive extension and does not increase the frozen challenge's reported exposure score.

The SR01 passes take 7.050 and 7.297 wall seconds and each record 324 successful native build returns from 324 compiler attempts. Its five producer files contain 318 nonblank lines, including a 55-line admission model. A read-only receiver reconstructs all twelve admission facts from declared policy, recorded calls and separately parsed source bytes; it does not use cohort expected labels to assign a verdict. Endpoint snapshots do not establish continuous file-system exclusion or rule out an unobserved replace-and-restore event between observations.
