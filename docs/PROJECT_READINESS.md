# Project readiness

## Scientific implementation

The project implements execution correspondence as a layer distinct from
predicate replay. Plan reception, scientific-verdict reconstruction, native
command and byte binding, and request-history preservation are executable checks
with positive controls, purpose-built contradictions, and failure-path tests.

The strongest controlled results are preserved without changing their scope:

- six valid correspondence records pass all three layers; among 18 specified
  association contradictions, predicate replay rejects 1, plan reception rejects
  8, and native binding rejects all 18;
- the paired history intervention changes all six faulty-decoder judgments while
  the 24 corresponding artifact pairs remain byte-identical, and all 12 records
  with required history removed are rejected;
- all 10,134 projected target judgments are preserved, while most self-contained
  inputs are slightly larger than their sources, so projection is an audit
  boundary rather than a compression claim;
- the state-budget activity accounts for 900 cases, 1,872 extractor calls, and
  1,116 stage obligations.

## Engineering quality

The code repository is separated from the complete evidence object. It provides
an offline core environment, a recorded scientific-dependency environment,
one-command quick and full validation, focused module entry points, native smoke
acquisition, continuous-integration definitions, license boundaries, compact
fixtures, and a controlled evidence importer. Validation logs distinguish
execution, explicit skip, failure, and timeout.

Immutable schema identifiers, dependency identities, and byte digests remain
where the scientific method requires them. Editorial work directories, delivery
manifests, virtual environments, caches, and repeated historical work trees are
not part of the source repository.

## Artifact-review position

The package provides the properties expected of a functional research artifact:
it is documented, internally consistent, locally installable without network
access, exercisable, and checked by positive and negative controls. Its structure,
entry points, tests, and evidence boundary also make it a strong candidate for a
reusable-artifact assessment. Badge decisions remain the responsibility of an
external artifact review.

Public archival availability requires deposition in a persistent repository with
a stable identifier. Results reproduced requires another person or team to
obtain the main results. The authors' clean-environment runs and separate
receiver implementations do not establish either status.

## Remaining evidence boundaries

- The complete LLVM matrix is received from bound retained records; a new
  acquisition still requires a matching LLVM toolchain and Eigen headers.
- The complete SandMark frame is received from bound retained records; a new
  acquisition still requires separately licensed inputs and its Java setup.
- The GeMTest compatibility run exercises the locked upstream source but does
  not rank frameworks or cover every surrounding plugin version.
- The CTF API comparison reuses retained native observations and therefore does
  not add an independent native sample.

These boundaries limit stronger external-reproduction claims. They do not change
the controlled correspondence, request-history, projection, or state-budget
results that form the central evidence.
